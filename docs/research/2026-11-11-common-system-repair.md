# E54共同底座修复

Issue #729。用户要求先修复masscan、flex、xz暴露的共同问题，并处理mozjpeg恢复上下文容量；本阶段为工程修复，零Provider，不重跑H0/R2比较，不改论文v0.10。

## 共同机制

- **轻量验证**：独立`ExecutableSmoke.accepted_exit_codes`默认仅0。非零正常退出必须由作者依据明确声明，超时、信号及执行器错误不能声明为通过。系统生成受信Python验证包装器，执行原命令、保留原生退出码，并同时检查输出；只有整个断言成立才退出0。原容器与verify.sh/交付smoke运行同一包装器，不改模型输出或忽略错误。masscan依据src/main-conf.c的print_version/exit(1)修正新工程参考；旧E54参考不改。
- **外部工具链**：源码依赖的获取、配置、编译、安装仍属于主项目的dependency阶段，各拆为独立步骤，按requires排序；仅dependency步骤可将workdir设为`/workspace/dependencies`内路径。先显式创建目录，安装前缀和PATH在所需命令中明确表达。主项目configure/build仍在仓库，混合多个阶段、任意删除和屏蔽失败继续拒绝。成功依赖仍进入配方和干净重建，不因原容器已有而省略。
- **原文件保护**：内容、链接类型及权限不变的重写不因inode/ctime变化失败。原C/C++源码、测试及未声明原文件内容继续保护。顶层`po/*.po`仅对原本存在且可识别的空msgid头，忽略POT-Creation-Date和X-Bugs字段的位置；X-Bugs内容、其余头、注释及翻译正文仍受逐字保护。Workflow与产物观察共用相同检查。输出另列元数据前后SHA，不声称所有原文件字节均未变；不整体放行po目录，也不由Agent申请修改权限。
- **恢复上下文**：保留完整当前任务/方案/最后失败命令；初始材料、旧命令日志与历史证据按层裁剪，完整原件另存，明确缺失内容和日志路径。唯一剩余的大型压缩证据仍能继续有界压缩，保留AI/Tool配对语义，无新增摘要模型。必要不可压缩输入本身超限时仍报告容量停止，不能保证任意输入永不超限。
- **分层结果**：异常出口仍尝试检查受保护输入；后续异常不抹掉已经观察到的主构建层。整体交付仍需独立验证、重建和清理；主构建通过不等于可复现交付通过。原实验标签不回写。
