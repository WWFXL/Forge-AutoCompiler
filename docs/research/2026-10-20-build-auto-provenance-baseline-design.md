# 配方溯源接口与强工具基线候选

跟踪 #504。当前工作是零 Provider 的基础设施与方法设计，为排除 RQ1 比较中的手工编号负担提供独立接口；本文件不是新真实实验的预注册，也不代表已完成消融。

## 已观察问题与设计目的

#502 的固定24槽比较尚在运行。已完成多个工具臂在实际构建与固定完整测试通过后，误将 smoke ID 用作 supporting build ID，或把 smoke 纳入 recipe、提交乱序 recipe。拒绝和恢复成本全部保留。它们属于配方溯源操作问题，不能解释成项目不可构建，也不能把方案路径与工具路径的全部差异归于初始规划。

新候选仅替换 `submit_verified_build` 的参数接口：模型无参数提交时，系统重新读取权威 Session，选择最后一个 exit0 且未超时的 build 作为 supporting；按权威记录顺序取得全部成功 dependency/configure/build/artifact_stage 作为 recipe，排除 clone、inspect、diagnostic、smoke、失败与超时。选择结果写入独立 ledger 事件，然后调用原工具的严格提交逻辑。

这不是最小配方优化器：若出现多次成功配置或构建，它们均可能进入配方，严格 replay 仍可拒绝。它不猜测缺失步骤、不修复命令、不从人工参考选择方案、不改变命令角色、不清除失败记录、不转移或补造固定测试凭证。依赖/配置/构建操作使旧测试凭证失效的现有规则仍有效。自动编号消除的是显式 ID 操作负担，不承诺所有构建历史都可直接重放。

## 公平性与验证边界

读取工具、状态材料、批量调用、Shell、原始源码不变、固定完整测试、精确交付、不可变镜像、clean replay 和清理均沿用原工具服务。提示词仅替换提交接口说明。接口候选目前不被 #502 引用，不修改其 manifest、59个组件或原始观察。

自动ID还使工具Agent不必等命令返回编号后再发起一次模型请求，因此允许它在同一响应中提出构建、测试、暂存及最后提交，系统仍按序执行；不得为了保留方案路径优势而禁用这种批量操作。零Provider工具门禁会直接验证这一批量路径。未来观察的差异属于实际完整接口之间的比较，不能归因成纯粹的“规划思维”效果。

独立模块为 `backend/packages/harness/deerflow/compile/plan_agent_provenance.py`；针对性测试验证按序选取成功阶段、拒绝不存在的 supporting、每次读取最新权威记录、原服务拒绝原样返回，以及提示词只修改提交说明。通过这些测试只能说明接口委托正确，尚不能说明真实模型或 Docker 资格通过。

## 后续决策

先完成 #502 全24槽、封存和独立审计，再依据完整拒绝分布决定是否启动三构建系统小样本探针。若启动，必须另行冻结身份、样本、共同资源、费用、截止与零 Provider 门禁；与新鲜 plan 路径配对，全部成本纳入共享 $20。样本由已观察问题后选择，不能称新的独立 holdout；不将旧手工接口到新自动接口的跨批差值当作单因素因果效果。新鲜 plan 对新工具的配对只描述该固定任务集与实际接口，不推广为成熟 Agent 排名。

本设计不改变硕士论文主线，也不放宽严格终点、已有停止规则或科学主张。
