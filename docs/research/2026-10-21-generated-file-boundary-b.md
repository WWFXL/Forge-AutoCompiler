# 生成文件任务边界 B：用户决定与可行性检查

2026-10-21，Issue #573。主线仍为“面向 C/C++ 仓库自动化构建的状态感知动作选择与验证方法研究”。本阶段属于任务定义和基础设施可行性验证，用于解除标准 bootstrap 与全部原文件 SHA 保持之间的任务冲突，不产生策略效果结论。

## 已确认的任务定义

用户明确选择 B：Autotools 生成配置模板和辅助脚本属于正常构建环节，允许生成文件，作者源代码和测试不能改。今后新任务采用此定义；旧实验全部保留，不重新分类为成功，也不把新结果补入旧九槽。

| 文件角色 | 规则 | 示例及限定 |
| --- | --- | --- |
| 作者源代码、作者测试 | 内容、路径集合和文件类型保持；禁止修改、删除、替换或通过新增源码/测试绕过原文件 | 作者 `.c/.cpp/.h`、测试源文件、测试脚本及其数据/预期结果 |
| 构建语义输入 | 同样保护；不能借“修构建”改变目标、依赖、功能或测试义务 | `configure.ac`、`Makefile.am`、手写 `.m4`、手写 `Makefile.in`、自定义生成脚本 |
| 已有的工具生成文件 | 只允许预声明的路径由指定标准生成过程更新 | 有上游生成关系依据的 `configure`、`ac_config.h.in`、生成型 `Makefile.in`、工具提供的辅助脚本；不是按文件名或目录整体放行 |
| 新生成文件和编译产物 | 在任务中声明生成关系或输出范围，记录来源；不能成为绕过作者源码/测试保护的入口 | `config.h`、配置后的 `Makefile`、构建目录中的对象/库/可执行物和工具缓存 |

角色由上游生成关系和任务审阅确定，不由扩展名确定。例如，生成型 `config.h` 可以是合法输出；作者手写头文件仍是受保护源码。`Makefile.in` 若是手写输入则保护，若是从受保护 `Makefile.am` 由指定 Automake 生成才可声明可写。不能笼统放行 `m4/`、所有 `.in` 或所有 Shell 脚本；角色不明时先审阅，不让实验 Agent 自行授予权限。

## 后续共同执行接口必须落实的规则

1. 在初始模型调用和策略执行之前，为每个任务冻结 exact commit、受保护文件集合、精确可更新路径、标准生成命令/工作目录、工具与镜像身份、必要输入和生成关系依据。新的输出目录/缓存范围需单列，不能覆盖受保护路径。已有结果只能用于开发诊断，不能据此给独立评估项目补特供白名单。
2. 三策略共用同一任务清单和检查器；初始规划、工具操作和失败恢复的权限一致。恢复 Agent 不能修改作者源码、测试、构建语义输入或运行时扩大权限。
3. 生成操作要记录命令、退出状态、受保护文件检查和生成物前后 SHA/类型；失败过程也保留变化记录。生成路径白名单和最终哈希本身不足以证明工具来源，正式接入还需约束实际写入过程、核验生成来源，防止手工改输出、先改输入再恢复或符号链接绕过。
4. 在同镜像、干净源码的 replay 中重新执行生成/构建，并执行同一文件边界检查。保护项变化或未声明已有文件变化仍拒绝；完整固定测试、功能配置要求、精确交付、产物一致性和实际 cleanup 保持，测试义务不能由 Agent 降低。
5. 作者测试源码不改不等于测试确实执行；仍由系统绑定完整测试命令和预期覆盖。新定义不允许关闭应测功能、减少用例或篡改预期结果来获得通过。

## 完成范围与下一步

负责人边界选择及生成关系可行性已经确认。该夹具只验证实际生成、阶段边界哈希、简单修改识别和微型项目重放；它没有实现生产权限检查器，也没有验证任意 Shell 的中途写入、符号链接安全、真实项目资格或三策略共享接入，不能声称 B 已端到端上线。

下一步实现独立的新共享文件边界接口，先补生成来源/路径/绕过负例，再审阅真实项目生成关系并执行零 Provider 完整资格，之后冻结独立策略比较。初始方案来源仍是主要对照因素，三策略采用同一新任务边界，避免把共同裁判变化当成某种规划的收益。旧 libconfig 九槽、全部冻结组件、RQ3 旧分母不变；不因这些结果更换主线或宣布两个创新点已经成立。

本次不调用付费 Provider，旧共享20美元和四小时时窗已结束，不从余额中自动续跑。用户选择 B 解决了任务边界决定；共同接口实现可在已有工程授权下推进，新付费运行仍须具有有效预算和窗口。
