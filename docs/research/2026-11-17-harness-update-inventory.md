# 本轮轨迹驱动Harness更新清单与版本定义

2026-11-17；Issue #807。类型：已有结果分析与版本整理。范围为2026-11-16至17日围绕libffi的离线迭代；本次没有模型调用、新构建或论文修改。

本轮由Codex承担Super Agent职责：结合当前实现及真实失败轨迹诊断问题，提出更新，经用户指令实施，再通过工程回放和真实自主运行观察效果。这是一轮人工审核下的离线Harness优化；尚未实现自动运行的Super Agent优化循环。

## 3. 提示、工具和上下文如何组装

### 规划Agent

LH-v0和LH-v1都使用P0共同提示`SIMPLE_PROMPT`及初始工具约束。LH-v1额外启用`inspect_planning_dependencies=True`，加入`PLANNING_DEPENDENCY_PROMPT`及真实环境查询工具。指导要求按作者声明核实必要依赖，把缺包安装写入dependency步骤；没有给规划Agent宏名、包名答案或libffi完整成功指令。

### 恢复Agent

LH-v0使用[原R2候选](../../benchmarks/fixtures/recovery-harness-system-context-gpt61sol-v1/candidate.json)。LH-v1使用[当前候选](../../benchmarks/fixtures/verified-macro-recovery-experience-v1/candidate.json)，其指导为原R2依次追加[通用诊断原则](../../benchmarks/fixtures/dependency-diagnosis-guidance-v1/guidance.md)、[诊断顺序](../../benchmarks/fixtures/dependency-diagnostic-order-v1/guidance.md)及[已审核宏经验全文](../../benchmarks/fixtures/verified-macro-recovery-experience-v1/experience-guidance.md)。当前候选指纹为`9de184d72f39866fd832a985f720293d6432ccd7c8a033e94f81f2376d4836d8`，该指纹按候选对象计算，不是指导文件的字节SHA。

运行时另外装配环境查询、`DIAGNOSIS_PROMPT`和`MEMORY_PROMPT`，将真实失败交接、当前方案、依赖缺口及证据快照放入任务上下文。相关实现为`recovery_environment.py`、`dependency_diagnosis.py`、`recovery_diagnostic_memory.py`及`simple_build_agents.py`，其精确内容由版本清单定位。

已审核经验是恢复指导的一部分；本轮没有实现基于经验库的自动检索，不应描述为规划/恢复双方自动检索经验。诊断快照随请求更新是任务内事实管理，与多次检索历史经验不同。

### 上下文管理

LH-v1的`RequestContextBudget`为输入64000、最多输出32768、模型窗口1000000 Token；输出仍受原模型更小设置约束。使用cl100k_base估算并加25%及2048余量，真实计费依据Provider usage。超过工作预算时按完整AI/Tool组处理，保留任务、当前方案及最后失败命令。诊断显示最多六候选，核实过的候选优先，完整原记录保留。

## 4. 同期环境与执行政策变化

这些变化必须与Harness内容一起登记，后续比较时分别固定。

- LH-v0镜像：`sha256:8123220a201ac4d00cda0dc985b9db7227cd909bb93ca6c25fd82cafce5cd887`。
- LH-v1镜像：`sha256:d483ffa7b71b9545cff9555f6c92b6281a3f826ce006e2d09134cbdca92f8aa1`；含依赖查询索引，未预装本例缺失的`libltdl-dev`。
- 文件变化处理由原文件即时保护转为`posthoc-review-v1`（`a0b85e4d`，PR #767）：记录变更后继续构建，将语义审查单独保留。它影响任务推进与结果解释，不是Agent诊断能力提升；不能为某个比较组单独采用不同政策。
- 构建目标仍是主要库构建、独立交付检查和原归档干净重建；完整作者测试未要求。模型、原libffi源码版本及主要任务目标不变，不代表环境和执行政策全部相同。

后续如评价整轮更新，应统一镜像、文件政策、评价和资源，明确只比较哪些Harness内容。不能直接将两个历史快照的差值当作经验提示的单变量效果。本轮只确定历史版本，未装配下一批两组执行入口。

这些是同一已暴露项目不同独立运行的描述性观察。它们展示诊断路径变化，尚不能给出新增项目成功率、各组件因果收益或稳定降本。#805比#795开销更高，也说明当前更新不是各项指标单调改善。#801已核实缺包但容量停止的失败和其他未完成轨迹均按原报告保留。

当前可以使用的结论是：轨迹诊断指导了提示、工具、证据管理和上下文更新；明确经验在本例被核实并采用，容量修复后该流程能够真实完成。经验只在恢复生效；规划主动预防同类依赖错误仍是待评价问题。
