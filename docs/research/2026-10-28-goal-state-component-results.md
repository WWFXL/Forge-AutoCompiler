## 自然状态动作案例与恢复边界

槽13 snappy/状态/第二重复的初始方案明确设置SNAPPY_BUILD_BENCHMARKS=OFF。首次configure后实际CMakeCache记录该值为BOOL/OFF，固定目标要求ON；系统记录violated，命令前沿与缓存原字节SHA同时保存。其余依赖探测和测试目标满足；作者源码存在该option声明，因此选择一次直接修订：

```bash
cmake -S /workspace/repo -B /workspace/repo/build -DSNAPPY_BUILD_BENCHMARKS:BOOL=ON
```

修订执行约6.13秒，随后重新观测为satisfied，再执行一次build、原固定测试、精确静态库交付和完整clean replay。该槽9次请求全部属于初始规划，0Agent恢复、0额外恢复Provider请求；完整费用0.0455190美元、258.18秒。旧配置命令与新修订均保留在recipe/命令审计中。缓存原证据SHA为8c815d02ec94e5fe6bf0363057e0c8cd5ac86f65a4a17b6b1c110ab9f8135966，方案保存在slot-13/snappy-plan/agent/goal-rule-plan-2.json。

槽14 snappy/当前/第二重复也关闭基准测试；先build后固定检查拒绝，再Agent恢复，且补装依赖，最终完整通过。它与槽13形成同类错误下不同发现时机和动作的案例对照，但初始方案/依赖动作不同，不是同源固定方案反事实，也不能从一例估计平均节省或自然动作触发率。

其余恢复全部保留：槽1/10 simdutf当前版分别存在快速测试开启/工具关闭等配置目标遗漏，编译后固定检查拒绝，再Agent修订并成功；槽11状态臂编译完成却预期build/libsimdutf.a，槽18状态臂预期build/yaml-cpp-tests，二者在路径检查退出86后由Agent恢复。这两个是产物预期错误，不能写成编译器失败或配置诊断失败。五次Agent恢复均计入全部费用，不以终态成功擦除前序失败。

本批共17次配置观测，16次satisfied、1次violated，0unknown；包括配置后/首次build前及修订后重复观测，不是17个独立任务。一次自然直接修订支持该路径确已真实发生并完成任务，不足以证明直接修订的平均因果收益。所有23次Agent候选均通过tool_call接收，本批没有JSON文本接收的自然效果观察；不能以旧失败跨批差值评价共同Harness修复效果。
