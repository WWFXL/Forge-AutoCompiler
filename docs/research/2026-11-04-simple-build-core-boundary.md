# 简洁构建论文核心版本与比较安排

2026-11-04，Issue #675。承接[简洁任务设计](2026-11-04-simple-build-task-design.md)和[最小实现](2026-11-04-simple-build-implementation.md)。用户确认：先补齐最终论文核心组件，再固定版本进行比较，避免每增加一个小功能重跑全部基线。

本阶段是必要接入与工程试运行，不是模型效果实验。旧E30/E33、E01及E35–E41按各自模型、任务和版本继续使用；简洁任务减少了工作量，不能用跨批差值称算法加速。论文v0.6现有章节不改写为新版本已取得效果。

## 核心系统边界

| 组件 | 本版保留的行为 | 本轮接入 |
|---|---|---|
| 规划Agent | 读取公开简洁目标与作者文件，返回依赖/配置/编译动作 | 接到统一入口；不含私有参考和测试脚本 |
| 状态观察与Workflow | 实际配置/生成器/命令结果/主要组件覆盖；有效前缀与首变化后缀重执行 | 复用#673，不扩规则大全 |
| 失败恢复 | 遇真实失败返回修订方案；执行权由Workflow持有，之后继续后续阶段 | 保留既有方案恢复；本轮不切换新的局部工具恢复 |
| 同项目方案 | 精确匹配时跳过规划，执行先前完整成功的实际动作；失败回到正常恢复 | 新SimpleProjectRecipe，仅运行标签plan_id可不同；源码/镜像/平台/目标/澄清/并行资源均匹配 |
| 跨项目经验 | 相同构建系统、排除同族；利用当前公开目标/已读源码/实际失败选择建议 | 复用原经验库和排序；每次规划或新恢复任务开始一次，任务内固定 |
| 结果检查 | 主要构建、作者测试、交付、干净重放和完整完成分报 | 各方法使用共同公开任务与私有参考，作者CTest统一串行 |

可执行方案只从完整通过、原源码保持、交付/作者测试/重放及清理成功的本版运行登记，保持来源和实际验证层级。原复杂任务的ProjectRecipe不能未经重新执行就标成简洁任务精确命中。失败与部分成功轨迹仍能作为有来源的条件建议，不升级为可执行的已验证成功方案。

本版经验改变上下文或复用命令，不自动改写Harness代码，不声称实现了递归自进化。新分类器、联网搜索、多Agent体系、学习型排序与产品UI迁移均不作为这次论文比较的前置工作。

## 统一比较入口

`scripts/forge_simple_system.py`提供Forge、经验Forge、强工具Agent、CXXCrafter四个方法选择；当前CLI仅支持离线脚本模型。正式Provider由已授权启动器注入，并绑定新的固定样本、顺序、预算及时窗；本轮不读取模型凭据。

- **Forge基础版**：模型规划→Workflow执行/实际观察→必要时方案恢复→共同外部检查。
- **Forge经验版**：先查同项目精确成功方案；命中跳过规划。未命中则一次跨项目检索并规划。每次新恢复任务重新选一次，任务内所有读源码/工具交互沿用该次快照。任务后新方案另存，不自动泄漏给当前比较的后续重复。
- **强工具Agent**：共享只读源码/日志工具与严格Shell、资源和结果裁判；由Agent逐条选择依赖/配置/编译/诊断指令，提交实际成功命令组成的有序配方。不给它Forge阶段动作建议，也不强加Workflow全局阶段排序。外部主构建接受后停止Agent，再独立测试/交付/重放。
- **CXXCrafter社区参考**：保留已安装社区源码的Parser/Generator/Modifier/Judge和Dockerfile迭代；每次SDK调用注入同一个公开目标并计量。仅固定镜像/资源/输入源码位置；独立参考与作者测试不交给其模型，外部失败不回送Modifier。原生Dockerfile从空源上下文关闭缓存重建两次，共享主组件识别和分层结果、逐文件交付内容比较。其Harness、依赖扫描和镜像构建方式仍不同，是完整系统参考，不能把差值全部归因于状态组件或冒充论文原版。

CXX源码保护跨镜像核对内容、链接和权限；Forge运行内还核对文件身份。二者不因此声称覆盖所有瞬时写入。原生CXX可能使用宿主解析/额外模型Judge，开销全部计入；正式比较需披露，而非强行改造成Forge。

## 统一安排论文实验

1. **新项目系统比较与经验消融**：同一批项目、模型、环境与公开目标，交错方法顺序，安排基础Forge、经验Forge、强工具Agent、CXX参考。初始无该项目的精确简洁方案；经验种子固定并登记来源/目标族暴露。主要问题是总体完成、费用与耗时；基础/经验Forge的配对结果回答跨项目经验增量。重复不当独立项目。
2. **同项目方案复用**：单独固定已获得的简洁成功方案，与重新规划配对比较，分别报告精确命中、回退和恢复；来源方案获取费用单列并做累计成本分析。不能把首次制库当免费，不能与新项目成功率拼接。
3. **状态组件消融**：保持相同公开目标与初始方案，改变实际观察/动作选择组件。若新简洁目标下没有自然触发，不人为制造错误后称自然收益；旧E01仍按原目标解释，新任务是否需补相同设计由自然轨迹决定。

建议先以六个具有自然主要二进制/库产物、覆盖三类构建系统的项目、两重复×四方法组织48次系统比较；具体项目及资源待对作者构建说明和独立参考作一次集中核对后固定。头文件库是否存在自然主要可识别产物必须事前说明，不以方法成败筛样本。不把这份安排当作已经冻结/授权的48次运行协议。

主指标包括主要构建完成率、到主要构建的时间、全部初始/读取/输出/失败/恢复模型费用；交付、原作者测试、构建与测试重放、完整完成另报。全分母保留失败、超时与未观察；共同完成配对只作辅助效率分析，测试失败不抹掉主要构建成功。初始规划、恢复、Shell、测试与重放时间分开，避免把外部测试耗时全部归于模型。

## 版本与后续修改

本核心版本完成接入后固定代码/样本/经验库。小增强先做组件配对；若改变最终系统主要行为，再补新完整版本与主要基线。旧结果仅支持当时版本，保留负面结果，不全部作废，也不直接挪作新版结果。后续不以无限完善系统拖延论文主比较。
