03 · 研究缺口

从“看起来成功”到“严格可复现成功”

04 / 13

一次成功需要连续通过五层证据；任何一层失败，都不能用前一层替代。

S1 · Build

构建完成

配置、编译和链接命令真实执行并正常退出。

S2 · Artifact

产物有效

目标文件存在、非空、类型与路径符合任务。

S3 · Function

功能正确

预声明的最小消费者或任务级 oracle 通过。

S4 · Provenance

来源合法

产物来自记录的源码、构建系统与允许动作。

S5 · Replay

干净重建

在空环境按冻结配方重新产生合格结果。

退出码为 0

可能只安装了依赖，或者构建了错误目标。

产物确实存在

可能来自旧缓存、错误源码或未记录操作。

第一次功能通过

仍可能无法在新的空 workspace 中重现。

严格成功定义：S0 身份有效，并且 S1 ∧ S2 ∧ S3 ∧ S4 ∧ S5成功判据

06 · 反馈粒度

研究目标不是“越详细越好”，而是寻找最小充分信息

07 / 13
C0 · 普通失败基线
{
  "accepted": false,
  "reason":
    "verification_failed"
}

测量 Agent 自行诊断能力。

T1 · 验证证据增量 1
{
  "code":
    "target_mapping_invalid",
  "path": "lib/libdemo.a",
  "expected": ["shared"],
  "actual": ["static"]
}

测量机器确认事实的价值。

T2 · 可操作目标增量 2
{
  ...T1 fields,
  "repair_goal":
    "提交与目标类型和
    路径合同一致的候选"
}

测量抽象行动指导的额外价值。

统一禁止：shell 命令、argv、补丁、正确候选内容、其他实验分支信息和隐藏 evaluator 断言。
Treatment 同时改变信息内容与结构，因此不解释为“纯 JSON 格式效应”干预定义

独立验收

clean replay 与 cleanup 完成且无 managed orphan。

10 · 完整系统实验

机制有效后，再评价整个 Forge 系统

11 / 13

Default Build

标准构建命令，无 LLM 修复。提供最低自动化基线。

基础基线

CXXCrafter-style

Parser、Dockerfile Generator、Executor、Judge 与整体修订。

方法基线

Forge w/o Feedback

保留 Workflow、Session 和严格评价，移除合同反馈暴露。

系统消融

Full Forge

Workflow、Agent、候选合同反馈、external evaluator 与 replay。

完整系统

受控方法比较 · 主实验

共享 repository@exact_commit、公开任务、模型、环境、工具权限、预算、停止规则和统一 external evaluator。

原生系统比较 · 补充实验

允许各方法使用原生镜像和策略，更接近产品能力，但差异来源更多。

公平边界：所有系统看到同一公开任务说明；隐藏 oracle 只供共同 evaluator 使用。不能把论文的 `587/752` 直接作为本地基线。
公开实现不能稳定复现时，名称必须使用 CXXCrafter-style baseline系统评测

11 · 预期结果

预期结果是可证伪假设，不是预先写好的结论

12 / 13
机制实验三种均可接受
C0 < T1 ≈ T2

确定性证据有用，额外 repair goal 没有稳定增益。

C0 ≈ T1 < T2

错误事实不足，Agent 还需要抽象行动目标。

C0 ≈ T1 ≈ T2

Agent 可自行诊断；反馈机制不应成为主创新。

系统实验
  • Full Forge 可能提高严格成功率和结果可信度。
  • 原始 build completion 未必明显优于 CXXCrafter-style。
  • 验证和 replay 会增加固定时间开销。
  • 更少的无效迭代可能抵消部分 token 与费用。
  • 不同 failure stratum 可能需要不同最小反馈。

理想结论不是“反馈越多越好”，而是识别不同自动化编译失败所需的最小充分证据，以及它带来的可靠性—成本权衡。

探索性结果只支持继续检验，不支持提前声称总体效应假设边界

12 · 贡献与路线图

先建立可信机制证据，再扩展为完整自动化系统

13 / 13
方法贡献

有界合同反馈

从确定性 finding 生成不同信息粒度、无答案泄露的修复反馈。

实验贡献

同状态机制比较

从可恢复失败 checkpoint 派生分支，隔离 feedback exposure。

系统贡献

严格统一评价

把候选、功能、来源、clean replay 和成本纳入共同评测。

01 · 零 Provider qualification证明 checkpoint 同源、反馈唯一差异和完整闭环。
02 · 反馈机制实验比较 C0 / T1 / T2，按 failure stratum 报告。
03 · 完整系统实验统一 evaluator 下比较成功率、时间、费用和轮次。
04 · 后续扩展解析构建元数据，Agent 生成候选合同，用户只处理歧义。

当前论文先回答：给定可信任务合同后，如何让自动化编译的修复过程更有效、结果更可信、证据更可复现。
