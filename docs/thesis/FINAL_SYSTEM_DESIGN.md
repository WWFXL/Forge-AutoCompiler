# 最终系统组件与评价配置

日期：2026-11-12；版本：v1.0；Issue #752。本文固定后续评价采用的研究配置，不修改产品全局默认或历史实验身份。

## 1. 核心配置

采用P0初始规划＋初始规划工具执行约束＋规则状态路由＋R2方案恢复＋Workflow执行＋独立主结果验证。在线模型保持deepseek-flash、thinking low。

这一组合是E57的B组实际配置，12项目完成11项，在线费用0.4971639美元、113次请求、累计1257.90秒。它并非未测试的组件拼接；其相对其他完整系统在独立新项目上的综合效果仍需集中评价。

选择P0而非P4，是因为E57中P4虽然降低多数共同完成项目的费用，但完整完成少一项、全批费用高39.7%。选择R2偏重任务完成：E55多完成flex，同时费用与时间增加。后续评价同时报告这些代价。

## 3. 实际流转及交接边界

输入固定源码、共同环境和简洁主要构建目的。若启用精确复用且找到身份一致的验证成功方案，直接装配方案；否则P0调用只读材料工具，提交依赖/配置/编译阶段动作。

Workflow执行当前动作并记录命令、工作目录、退出状态和输出。命令退出成功后，结合该阶段实际配置或产物观察决定能否推进；无法观察的事实不由Agent声明补成成功。当前阶段失败或后续进展失效时，状态路由检查直接动作的证据前提；无适用动作或动作仍未解决则调用R2。

R2接收当前方案、实际到达阶段、失败命令和日志、已成功依赖及必要保护约束，使用只读工具补充材料，返回修订方案。Agent不在容器中直接执行Bash修复，修订由Workflow执行；依赖/配置发生变化则使相关后续进展失效，从必要位置继续。完成主构建后，独立检查与干净重建决定交付结果。

例如某CMake仓库先生成配置再编译。编译阶段没有观察到预期配置时，若当前记录支持恢复配置，执行器先重建配置并重跑受影响编译；若日志表明缺少一个尚未纳入依赖的库且没有明确安全动作，则交R2调查作者依赖声明并返回安装和重新配置的修订。不会为每个库增加一条硬编码异常规则。

## 4. 状态感知的具体范围

状态表示包含阶段、构建系统、失败原因、实际命令/退出/终止、日志尾部、配置状态及主要产物状态。当前main-build路由的候选包括有明确作者最低版本与实际错误支持的CMake升级、已失效配置的恢复，以及未知产物的进一步观察；没有明确前提则使用Agent。

当前代码见`backend/packages/harness/deerflow/compile/build_state_routing.py`的`observe_state`、`candidate_actions`与`rule_choice`。每槽直接动作有数量及重复限制，避免规则循环替代恢复。

E01中作者option＋BOOL缓存＋显式任务目标的直接配置修订，是状态方法的历史受控证据；它的详细配置任务与当前简洁主任务不同。论文可用它解释机制的增量，但不能把其所有动作都列成当前默认，或把10/10解释为开放异常覆盖率。

## 5. 实现核对与配置身份

E57入口为`scripts/forge_planning_tool_comparison.py`，B方法键为`B_P0_enforced`。它调用共享`run_simple_system`，设置主构建验证、规则状态路由、P0、原R2，并启用初始规划工具约束。

`backend/packages/harness/deerflow/compile/simple_build_task.py`中的`propose_simple`以`current_plan is None`区分初始与恢复。执行约束由`enforce_planning_tools and current_plan is None`限定，因此本方案没有把约束扩展到R2恢复工具。两类Agent均返回结构化方案，模型自述不替代实际执行结果。

R2使用`benchmarks/fixtures/recovery-harness-system-context-gpt61sol-v1/candidate.json`，候选SHA-256为`270becfd8fe2c0c89d0d7ab8c820893cdc6ae7cdd9d2c50e95ecb11f84263743`。原指导保持，只按已有入口绑定共同提示。已有E57运行revision为`128dd9447975542833f9c05670eeb4fbaaad5758`；历史观察以该批报告和原证据为准。

产品通用入口仍按原调用参数工作。后续正式比较应显式传入研究配置，不能仅使用“Forge”名称而省略P0、工具、路由、恢复和验证版本。
