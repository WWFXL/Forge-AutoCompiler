# 论文核心论证与证据方案

日期：2026-11-12；版本：v1.0；跟踪：Issue #752。本文是论文组织方案，正文仍为v0.11，本轮不重排正文、不新增实验。

## 1. 统一研究问题

在固定在线模型的条件下，如何结合当前构建状态与历史构建轨迹，改善C/C++仓库的动作选择，减少重复探索，并完成主要构建与可复现交付？

论文用两项相互衔接的研究工作回答：第一项将项目特定方案与通用执行流程分离，利用实际状态选择直接动作或Agent恢复；第二项从上述执行留下的轨迹定位重复探索与交互问题，通过经验复用、提示指导和工具行为更新改善Harness，再用完整成本评价决定是否采用。验证机制为这两项工作提供统一结果依据。

贡献定位是自动化编译领域的方法与系统设计及实证分析。技术内容落在阶段进展表示、观测与动作前提、受影响后缀重执行、成功方案复用，以及提示与工具行为的可区分比较。

## 6. 当前完成程度与剩余关键工作

已经具备完整系统比较、固定方案消融、经验复用和Harness三组实验。后续重点是把确定配置放到独立新项目上作集中综合评价，而非继续证明系统“可以跑通”。

当前核心配置P0＋初始规划工具约束＋R2已在E57的B组实测11/12。还需要回答它相对强工具Agent/CXXCrafter在新项目上的完成、请求、费用和时间表现；接入精确复用后的组合效果另按重复项目分层。项目选择应优先扩展覆盖，避免例行增加同项目重复；任何重复都应有估计随机性的具体目的。

下一批设计前先统一共同环境和简洁目标，冻结项目、任务、方法与预算；所有方法计入完整规划/失败/恢复费用，未观察保持独立标签。无需为本轮论文组织重跑历史实验。
