# 第7章 总结与展望

> 本章为阶段性总结，已包含独立局部恢复比较。经验方法完成后仍需更新本章及摘要，不能将研究计划直接改为完成结论。

## 7.1 已完成研究与阶段结论

本文围绕C/C++仓库自动化构建中的项目差异、执行不确定性和完整任务判断，形成了先规划、再阶段执行、根据实际状态恢复的方法。模型生成项目特定方案，Workflow维护步骤与真实命令记录，状态选择器在适用配置点比较任务目标，支持受限直接修订及复杂异常的Agent方案恢复。修订后通过前缀保留和后缀重执行重新建立有效进展，最后使用原测试、精确交付、源码保持与同镜像干净重放判定完成。

已有完整系统比较表明，在所研究任务上，该方法可以相对强工具Agent减少模型费用，同时存在项目差异与时间取舍。八个已见任务的两次重复中，两方法均完整完成16次，Forge估费低22.9%，累计时间接近；独立24槽续段则显示不同完成数及共同成功子集的费用/时间取舍。这些观察支持基础系统的实用价值，不能推出任意仓库总体最优。

状态组件实验区分了提前发现偏差与直接动作替代恢复。固定方案下，四次有依据的配置修订均完整完成且无需新增恢复请求；独立规划时，状态增强没有相对仅目标的总体优势。恢复开关在所选五任务中将完整完成从2/5增加到4/5，伴随额外费用和时间。分层分析进一步说明，构建退出0、原测试、交付和重放分别承担不同的任务义务。

本文进一步实现工具辅助局部恢复，使Agent修订并执行目标阶段动作，凭真实成功记录交还Workflow。原20次比较暴露重复材料超限，四次失败完整保留；独立材料修复后8次比较中，两种方式均4/4完整，但局部工具含规划费高33.2%、累计时间高14.5%，只有一组配对费用与时间更低。这说明该能力可运行，但当前简单配置偏差中方案式已能高效恢复，增加连续工具交互未取得整体效率优势。

## 7.2 当前局限

当前配置语义主要覆盖显式CMake BOOL目标，复杂依赖、版本与路径问题仍交Agent，尚未形成一般依赖推断或学习型动作选择。基础版本恢复Agent主要返回修订方案；新增局部恢复允许执行已纳入方案的构建动作，已比较但仅覆盖两类已见配置偏差，尚未开放任意诊断Shell。没有证据表明它在复杂依赖或多轮异常中一定更优或更差。方案变化后的保守后缀策略也可能重做实际未受影响的步骤。

实验规模与项目独立性有限，部分任务已有开发暴露，不支持总体显著性和盲泛化主张。CXX参考存在工具、反馈和验收差异，不能作论文原版排名。默认smoke适配、时间宏与材料传递限制还可能造成非编译能力相关的未完成，需要在后续独立版本中处理。

经验模块尚处设计阶段。已有轨迹可以支持候选经验来源，但没有证明提炼后的条目更适用于后续项目，也未证明持续更新优于固定经验库。因此，经验驱动方法目前不能写入已完成效果结论。

## 7.3 后续研究与全文收束

当前已完成局部恢复与独立比较，证据支持保留方案式为基础选择、局部工具为可选能力。下一阶段可在固定基础执行能力上研究状态关联经验的提炼、适用判断和规划/恢复使用，并分别评价经验复用与持续更新。该后续工作尚未执行，需由用户决定，不因剩余预算自动启动。

必要的工具检索、联网搜索和角色分工围绕具体信息缺口实现，不以增加工具数量代替方法贡献。跨模型验证用于分析方法对基础模型的依赖，优先级低于核心方法与组件实验。最终将新旧版本的结果分别对应到方法，形成完整系统评价与关键消融。

论文写作与上述研究同步推进。当前已经形成任务、基础方法和实验正文，后续增量用于补全第5章、第6章待完成部分与最终结论。若经验方法只支持有限复用或呈现成本取舍，应按其实际证据定位，不为获得两个强结论放宽任务要求。
