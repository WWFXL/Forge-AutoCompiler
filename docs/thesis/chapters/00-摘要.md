# 面向C/C++仓库自动化构建的状态感知动作选择与验证方法研究

阶段初稿v0.11，2026-11-11，待作者审阅。

## 摘要（阶段稿）

C/C++仓库的自动化构建涉及依赖准备、配置生成、编译及产物确认。项目间的构建入口、工具版本与依赖组织存在差异，固定模板难以适配；完全交由大语言模型逐条操作，又会增加正常路径的交互和重复探索。本文研究在固定在线构建模型的条件下，如何结合当前执行状态与历史构建轨迹改善动作选择，并完成主要构建任务及可复现交付。

本文提出模型规划、阶段化Workflow执行与状态驱动恢复相结合的方法。规划Agent依据仓库材料生成项目特定动作，Workflow保存阶段目标、实际命令与有效进展；系统结合退出码、日志、配置和主要产物选择继续执行、受限直接修订或Agent恢复。修订后从首个变化位置重执行受影响部分，并独立检查主要产物、源码保持、交付和干净重建。在此基础上，设计历史轨迹驱动的Harness优化：一方面复用同项目已验证方案或检索跨项目条件建议，另一方面由离线优化模型分析历史交接、工具反馈和系统实现，提出固定版本的规划或恢复指导，再通过配对实验评价其效果。

九项目、三构建系统、两次重复的54次主构建比较中，基础Forge、经验Forge和强工具Agent分别完成18/18、18/18、17/18。基础Forge相对强工具Agent的在线模型估费降低60.5%，累计时间增加42.2%；经验Forge相对基础的在线费用降低52.5%，其中六次精确方案复用均零模型调用并完成实际重建。固定初始方案的30次组件比较中，四次有依据的直接配置修订均完成且无需新增恢复请求。这些结果说明，已确定动作的阶段执行和匹配条件下的方案复用能够减少模型交互。

离线Harness研究先考察规划，再根据恢复开销转向恢复策略。第二轮规划优化使初始费用降低18.2%，但总费用增加87.5%，显示探索可能由规划阶段转移到恢复阶段。结合系统实现生成的R2恢复指导，进一步在18项目、36次共享初始方案的配对运行中完成18/18个项目，H0完成17/18。R2在flex外部依赖构建超时后改为提供必要宏与工具，完成原默认主目标和干净重建；在stderred、sxhkd上，恢复费用分别降低48.2%和73.1%。全批模型费增加7.3%、累计时间增加23.6%，时间增量主要来自flex继续探索至完成。结果表明，历史轨迹与当前状态结合的Harness更新可以补全复杂恢复路径，并在部分项目减少恢复交互；其收益表现为完成能力与资源投入的共同变化。

## Abstract (Working Draft)

Automated building of C/C++ repositories involves dependency preparation, configuration, compilation, and artifact validation. Differences in build entry points, tool versions, and dependency organization limit fixed templates, while delegating every action to a language model adds interaction and repeated exploration. This thesis investigates how current execution state and historical build traces can improve action selection under a fixed online model and support primary build tasks and reproducible delivery.

The proposed method combines model-generated plans, staged workflow execution, and state-driven recovery. A planning agent derives project-specific actions from repository materials. The workflow records stage goals, executed commands, and valid progress. Exit codes, logs, configuration, and primary artifacts guide continuation, bounded direct revision, or agent recovery. Execution resumes from the first changed step, followed by independent checks of artifacts, source preservation, delivery, and clean rebuilding. Historical traces further support Harness optimization through validated same-project plan reuse, conditional cross-project guidance, and offline updates to planning or recovery instructions. The offline optimizer analyzes observed handoffs and tool feedback together with the implemented system interfaces; candidate versions are then evaluated in paired comparisons.

In a 54-run comparison across nine projects, three build systems, and two repetitions, base Forge, experience Forge, and a strong tool agent completed 18/18, 18/18, and 17/18 runs. Base Forge reduced estimated online model cost by 60.5% relative to the tool agent, with 42.2% higher cumulative runtime. Experience Forge reduced online cost by 52.5% relative to base Forge; all six exact-plan reuse runs completed actual rebuilding without model calls. In a separate 30-run fixed-plan component study, all four evidence-backed direct configuration revisions completed without additional recovery requests. These results show the value of staged execution and plan reuse under matching conditions for reducing model interaction.

Offline Harness optimization first targeted planning and then shifted to recovery in response to observed overhead. The second planning update reduced initial cost by 18.2% but increased total cost by 87.5%, revealing a transfer of exploration to recovery. The implementation-aware R2 recovery guidance was subsequently evaluated in 36 paired runs on 18 projects with shared initial plans. R2 completed 18/18 projects, compared with 17/18 for H0. For flex, R2 recovered from an external dependency build timeout by installing the required macros and tools, completing the original default targets and clean rebuilding. Recovery costs decreased by 48.2% for stderred and 73.1% for sxhkd. Across all projects, model cost increased by 7.3% and cumulative runtime by 23.6%, with the runtime increase primarily attributable to continuing flex until completion. The findings show that trace-driven, state-informed Harness updates can complete complex recovery paths and reduce interaction on some projects, with benefits expressed through both task completion and resource use.

**Keywords:** automated building; C/C++ repositories; state awareness; action selection; trace-driven Harness optimization; reproducible verification
