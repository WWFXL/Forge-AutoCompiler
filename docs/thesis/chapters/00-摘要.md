# 面向C/C++仓库自动化构建的状态感知动作选择与验证方法研究

> 阅读说明：本稿包含基础方法、工具局部恢复及实际经验方法的独立比较。各版本结果分别对应，方法实现不等于效果成立；负向、条件性与未观察结果均保留。

## 摘要（阶段稿）

C/C++开源仓库的自动化构建涉及依赖准备、配置生成、编译、测试及产物交付。不同仓库在构建系统、配置开关、依赖发现和产物组织上存在差异，单一固定指令难以覆盖完整任务；完全依赖大模型逐步操作，又可能在正常执行中产生不必要的交互。与此同时，命令执行成功并不意味着任务所要求的测试、功能与交付条件全部满足。针对上述问题，本文研究面向C/C++仓库自动化构建的状态感知动作选择与验证方法。

基础方法首先由模型依据仓库证据生成构建方案，再由Workflow执行器维护阶段依赖与实际命令记录。执行过程中，系统比较显式任务目标与实际状态：正常情况下继续执行；对具有作者选项声明和真实配置依据的特定BOOL偏差执行受限修订；复杂或未知异常交由Agent生成修订方案。方案变化后，从首个变化位置重新执行后缀，并使用原测试、源码保持、精确交付和同镜像干净重放确认完整完成。本文进一步实现状态关联经验：从真实成功和失败轨迹提炼带条件、动作与证据的条目，按构建系统、阶段和词项检索用于规划与恢复，并仅在任务终结后追加到后续可用经验库。

已有实验包括完整系统比较、固定初始方案消融、恢复开关比较及分层验证分析。在八个已见任务、两次重复的系统比较中，Forge与强工具Agent均完成16次任务，Forge模型估费低22.9%，累计耗时接近。在五份固定方案的30次组件实验中，三种处理的完整完成数分别为9/10、10/10、10/10，直接修订组四次配置纠偏全部完成，且无新增恢复模型请求。另一批独立24槽比较则呈现费用与时间的取舍。工具辅助局部恢复进一步允许Agent执行修订动作并交还真实进展；原20次比较的材料失败保留，独立修复后8次比较中两方式均4/4完整，但局部工具含规划估费高33.2%、累计时间高14.5%。新增六项目、两重复的36次经验比较中，无经验/原轨迹片段/结构化经验完整12/12、12/12、8/12；原轨迹和结构化均未取得总体优势，inja结构化在线费用低39.8%，保留局部收益与执行底座限制。另12次独立更新比较两组各5/6完整，含全部提炼费后更新组费用低8.7%、累计时间低7.3%，但仅两任务实际检索新来源。上述结果支持基础方法的实用价值，并明确恢复接口与经验方法的条件性取舍，不构成总体显著性、任意配置修复或普遍持续改进的结论。

## Abstract (Working Draft)

Automated building of C/C++ repositories involves dependency preparation, configuration, compilation, testing, and artifact delivery. A fixed command template cannot cover all repository-specific requirements, while delegating every execution decision to a language model may introduce unnecessary interaction. Moreover, a successful command does not establish that the requested tests, configuration goals, and delivery requirements have been satisfied.

This thesis investigates state-aware action selection and verification for repository-level building. A model first generates a build plan from repository evidence. A workflow executes the plan and maintains stage dependencies and command records. Explicit configuration goals are checked against observed state. The system applies a bounded direct revision when sufficient evidence exists for a supported Boolean option; otherwise, an agent produces a revised plan. Execution resumes from the first changed step. Original tests, source preservation, exact delivery, and clean replay under the same image are used to determine completion. A state-conditioned experience mechanism extracts conditions, actions, outcomes, and evidence from successful and unsuccessful traces, retrieves them for planning and recovery, and appends new experience only after a task has ended.

Existing experiments include complete system comparisons and component ablations. On eight previously examined tasks with two repetitions, both Forge and a strong tool agent completed 16 tasks. Forge used 22.9% less estimated model cost, with similar cumulative runtime. In a 30-run fixed-plan experiment, the three treatments completed 9/10, 10/10, and 10/10 tasks, respectively. All four direct configuration revisions completed without additional recovery model requests. A local tool recovery extension was also implemented and evaluated separately. After a context packaging repair, both recovery approaches completed 4/4 runs, but local tool recovery incurred 33.2% higher estimated cost including identical historical planning costs and 14.5% longer cumulative runtime. Original failures were retained under a separate identity. A separate 36-run experience comparison on six projects with two repetitions completed 12/12 runs without experience, 12/12 with raw trace excerpts, and 8/12 with structured experience. Neither experience treatment showed an overall advantage, although structured experience reduced online cost by 39.8% on inja. Failures included plan errors and execution harness limitations. In a separate 12-run update comparison, both banks completed 5/6 runs. Including all distillation costs, the updating bank cost 8.7% less and took 7.3% less cumulative time, while only two tasks retrieved newly added sources. These observations support bounded claims about the base method and conditional recovery and experience trade-offs, rather than population-level superiority or general self-improvement.

**Keywords:** automated building; C/C++ repositories; state awareness; action selection; agent harness; reproducible verification
