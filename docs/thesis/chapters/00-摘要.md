# 面向C/C++仓库自动化构建的状态感知动作选择与验证方法研究

硕士论文阶段初稿v0.11，2026-11-12。

## 摘要

C/C++开源仓库构建需要协调依赖准备、配置生成、编译与产物确认。项目间构建入口、依赖组织和生成目录的差异，使固定命令模板难以覆盖真实任务；完全由大语言模型逐步操作，则会增加正常路径的交互和重复探索。本文研究在固定在线构建模型的条件下，如何利用当前执行状态与历史构建轨迹，改善动作选择、任务完成及模型开销。

本文提出模型规划、Workflow执行与状态驱动恢复相结合的方法。规划Agent依据作者材料生成阶段动作，Workflow执行并维护有效进展，状态选择器综合阶段目的、退出码、日志、实际配置和主要产物，选择继续执行、有依据的直接修订或Agent恢复。方案改变后保留有效前缀，重做受影响后缀；独立检查确认主要产物、源码保持、精确交付和同镜像干净重建。在此基础上，研究历史轨迹驱动的Harness更新，包括同项目成功方案复用、跨项目条件经验，以及根据轨迹诊断提出的规划提示和工具执行约束更新。各候选通过固定版本比较决定采用与否。

九项目、三构建系统的54次主构建比较中，基础Forge、经验Forge和强工具Agent分别完成18/18、18/18和17/18。基础Forge模型估费比强工具Agent低60.5%，累计时间高42.2%。六次同条件成功方案复用均无需模型调用，实际重建及交付通过，时间比重新规划低12.1%；跨项目建议的收益则随材料适用性与恢复过程变化。固定初始方案的30次消融中，四次有依据的配置直接修订均完成且无需新增恢复请求。

历史轨迹驱动的提示更新呈现规划与恢复之间的成本转移：第二轮候选H2初始费用下降18.2%，总费用却因恢复增加而上升87.5%。进一步在12项目上分别比较旧工具行为、工具执行约束以及约束加P4提示，共36次。任务及可复现交付完成数为10/12、11/12和10/12，模型请求为132、113和152。工具约束组总费用低14.9%，节约集中在困难项目；P4在共同完成的10项目中有8项费用更低，但两个困难项目的额外投入使其总费用比约束基线高39.7%。这些结果表明，编译Agent的改进需要同时考虑提示指导、工具行为和后续恢复，以完整任务完成和全流程开销评价Harness更新。

## Abstract

Building C/C++ repositories requires dependency preparation, configuration, compilation, and artifact validation. Differences in build entry points, dependencies, and output directories limit fixed command templates. Delegating every step to a language model can instead add interaction and repeated exploration. This thesis investigates how execution state and historical build trajectories can improve action selection, task completion, and model cost under a fixed online build model.

The proposed method combines model-generated plans, workflow execution, and state-driven recovery. A planning agent derives stage actions from repository documentation. The workflow records execution and maintains valid progress, while the controller uses stage goals, exit codes, logs, configuration, and primary artifacts to choose continued execution, an evidence-backed direct revision, or agent recovery. A revised plan preserves its valid prefix and re-executes the affected suffix. Independent checks cover primary artifacts, source preservation, exact delivery, and clean rebuilding under the same image. Historical trajectories support validated same-project plan reuse, conditional cross-project guidance, and offline updates to planning instructions and tool execution constraints. Fixed-version comparisons guide candidate adoption.

A 54-run comparison across nine projects and three build systems completed 18/18 tasks with base Forge, 18/18 with experience Forge, and 17/18 with a strong tool agent. Base Forge reduced estimated model cost by 60.5% while increasing cumulative runtime by 42.2%. All six exact-plan reuse runs rebuilt and delivered artifacts without model calls, taking 12.1% less time than replanning. Cross-project guidance showed task-dependent benefits and recovery costs. In a separate 30-run fixed-plan ablation, all four evidence-backed direct configuration revisions completed without additional recovery requests.

Offline planning updates exposed cost transfer between planning and recovery. The second-round H2 candidate reduced initial planning cost by 18.2% but increased total cost by 87.5%. A further 36-run study compared legacy tool behavior, enforced tool availability, and the same enforcement with P4 instructions across twelve projects. Completed builds and reproducible deliveries numbered 10/12, 11/12, and 10/12, with 132, 113, and 152 model requests. Tool enforcement reduced batch cost by 14.9%, with savings concentrated in difficult projects. P4 cost less on eight of the ten jointly completed projects, yet additional expenditure on two difficult projects increased its overall cost by 39.7% relative to the enforced baseline. The results motivate evaluating planning instructions, tool behavior, and subsequent recovery together through task completion and full-process cost.

**Keywords:** automated building; C/C++ repositories; state awareness; action selection; Harness optimization; experience reuse
