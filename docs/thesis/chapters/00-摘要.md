# 面向C/C++仓库自动化构建的状态感知动作选择与验证方法研究

> 阅读说明：本稿包含基础方法、工具局部恢复及实际经验方法的独立比较。各版本结果分别对应，方法实现不等于效果成立；负向、条件性与未观察结果均保留。

## 摘要（阶段稿）

C/C++开源仓库的自动化构建涉及依赖准备、配置生成、编译、测试及产物交付。不同仓库在构建系统、配置开关、依赖发现和产物组织上存在差异，单一固定指令难以覆盖完整任务；完全依赖大模型逐步操作，又可能在正常执行中产生不必要的交互。与此同时，命令执行成功并不意味着任务所要求的测试、功能与交付条件全部满足。针对上述问题，本文研究面向C/C++仓库自动化构建的状态感知动作选择与验证方法。

基础方法首先由模型依据仓库证据生成构建方案，再由Workflow执行器维护阶段依赖与实际命令记录。执行过程中，系统比较显式任务目标与实际状态：正常情况下继续执行；对具有作者选项声明和真实配置依据的特定BOOL偏差执行受限修订；复杂或未知异常交由Agent生成修订方案。方案变化后，从首个变化位置重新执行后缀，并使用原测试、源码保持、精确交付和同镜像干净重放确认完整完成。本文进一步实现状态关联经验：从真实成功和失败轨迹提炼带条件、动作与证据的条目，按构建系统、阶段和词项检索，并逐条核对当前文件、作者声明和真实错误等必要信号，辅助规划与恢复；任务后追加只影响后续任务。

实验按版本独立评价完整系统、状态组件、恢复与经验。在八个已见任务、两次重复的系统比较中，Forge与强工具Agent均完成16次任务，Forge模型估费低22.9%，累计耗时接近。五份固定方案的30次组件实验中，三种处理完整9/10、10/10、10/10，四次直接配置修订全部完成且无需新增恢复模型请求。六项目、两次重复的48次经验比较中，无经验、旧结构化经验、新过程经验和逐条选择完整11/12、12/12、12/12、11/12。旧经验在线费用低6.1%、时间接近，但计入一次制库后更贵；新过程与逐条选择未取得整体优势，保留jsoncpp与highwayhash的局部节约。轨迹同时显示实际错误触发跨项目经验采用，以及清理建议被错误实例化、误删原有构建脚本的反例。另12次独立更新比较中，两库各5/6完整，含全部提炼费后更新组费用低8.7%、累计时间低7.3%，但只有两任务实际检索新增来源。另36次短动作经验比较中，三组完整10/12、12/12、12/12；相对旧来源经验，短动作组初始源码读取少33.3%、初始费用低9.8%，但恢复几乎抵消节约，全程费用仅低0.34%、时间更高，部分有利波动还出现在空材料任务。结果支持基础方法的实用价值，并说明经验选择、实际采用与正确动作实例化需要分别评价；结论限于所测任务与对应版本，不证明普遍持续改进。

## Abstract (Working Draft)

Automated building of C/C++ repositories involves dependency preparation, configuration, compilation, testing, and artifact delivery. A fixed command template cannot cover all repository-specific requirements, while delegating every execution decision to a language model may introduce unnecessary interaction. Moreover, a successful command does not establish that the requested tests, configuration goals, and delivery requirements have been satisfied.

This thesis investigates state-aware action selection and verification for repository-level building. A model first generates a build plan from repository evidence. A workflow executes the plan and maintains stage dependencies and command records. Explicit configuration goals are checked against observed state. The system applies a bounded direct revision when sufficient evidence exists for a supported Boolean option; otherwise, an agent produces a revised plan. Execution resumes from the first changed step. Original tests, source preservation, exact delivery, and clean replay under the same image are used to determine completion. A state-conditioned experience mechanism extracts conditions, actions, outcomes, and evidence from successful and unsuccessful traces, retrieves them for planning and recovery, checks entry-level file, declaration, and observed-error signals, and appends new experience only after a task has ended.

Experiments evaluate system performance, state components, recovery, and experience under separate versioned conditions. On eight previously examined tasks with two repetitions, both Forge and a strong tool agent completed 16 tasks; Forge used 22.9% less estimated model cost, with similar cumulative runtime. A 30-run fixed-plan experiment completed 9/10, 10/10, and 10/10 tasks across three treatments. All four direct configuration revisions completed without additional recovery model requests. A 48-run experience comparison on six projects with two repetitions completed 11/12 runs without experience, 12/12 with the existing structured bank, 12/12 with process-enriched experience, and 11/12 with entry-level applicability selection. Reusing the existing bank reduced online cost by 6.1% with similar runtime, but cost more when its one-time preparation was included. Process enrichment and entry-level selection showed no overall advantage, although local savings were observed on jsoncpp and highwayhash. Traces include an actual error that triggered cross-project experience adoption, as well as an incorrectly instantiated cleanup action that deleted an original build script. In a separate 12-run update comparison, both banks completed 5/6 runs. Including all distillation costs, the updating bank cost 8.7% less and took 7.3% less cumulative time, while only two tasks retrieved newly added sources. A further 36-run comparison of short action experience completed 10/12, 12/12, and 12/12 runs across the three treatments. Relative to existing source-level experience, short action candidates reduced initial source reads by 33.3% and initial cost by 9.8%, but recovery nearly offset the savings: total online cost was only 0.34% lower and runtime was higher. Some favorable differences also occurred with empty experience contexts. These results support the practical value of the base method and distinguish experience selection, adoption, and correct action instantiation. Claims remain limited to the evaluated tasks and versions rather than general continual improvement.

**Keywords:** automated building; C/C++ repositories; state awareness; action selection; agent harness; reproducible verification
