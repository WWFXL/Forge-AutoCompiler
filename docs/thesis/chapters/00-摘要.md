## 摘要（阶段稿）

C/C++开源仓库的自动化构建涉及依赖准备、配置生成、编译、测试及产物交付。不同仓库在构建系统、配置开关、依赖发现和产物组织上存在差异，单一固定指令难以覆盖完整任务；完全依赖大模型逐步操作，又可能在正常执行中产生不必要的交互。与此同时，命令执行成功并不意味着任务所要求的测试、功能与交付条件全部满足。针对上述问题，本文研究面向C/C++仓库自动化构建的状态感知动作选择与验证方法。

基础方法首先由模型依据仓库证据生成构建方案，再由Workflow执行器维护阶段依赖与实际命令记录。执行过程中，系统比较显式任务目标与实际状态：正常情况下继续执行；对具有作者选项声明和真实配置依据的特定BOOL偏差执行受限修订；复杂或未知异常交由Agent生成修订方案。方案变化后，从首个变化位置重新执行后缀，并使用原测试、源码保持、精确交付和同镜像干净重放确认完整完成。本文同时设计状态关联的经验提炼与复用方法，用于后续任务的规划和恢复，该部分尚待实现与实验验证。

已有实验包括完整系统比较、固定初始方案消融、恢复开关比较及分层验证分析。在八个已见任务、两次重复的系统比较中，Forge与强工具Agent均完成16次任务，Forge模型估费低22.9%，累计耗时接近。在五份固定方案的30次组件实验中，三种处理的完整完成数分别为9/10、10/10、10/10，直接修订组四次配置纠偏全部完成，且无新增恢复模型请求。另一批独立24槽比较则呈现费用与时间的取舍。工具辅助局部恢复进一步允许Agent执行修订动作并交还真实进展；原20次比较的材料失败保留，独立修复后8次比较中两方式均4/4完整，但局部工具含规划估费高33.2%、累计时间高14.5%。上述结果支持基础方法的实用价值及恢复接口的条件性取舍，不构成总体显著性、任意配置修复或经验持续改进已有效的结论。

## Abstract (Working Draft)

Automated building of C/C++ repositories involves dependency preparation, configuration, compilation, testing, and artifact delivery. A fixed command template cannot cover all repository-specific requirements, while delegating every execution decision to a language model may introduce unnecessary interaction. Moreover, a successful command does not establish that the requested tests, configuration goals, and delivery requirements have been satisfied.

This thesis investigates state-aware action selection and verification for repository-level building. A model first generates a build plan from repository evidence. A workflow executes the plan and maintains stage dependencies and command records. Explicit configuration goals are checked against observed state. The system applies a bounded direct revision when sufficient evidence exists for a supported Boolean option; otherwise, an agent produces a revised plan. Execution resumes from the first changed step. Original tests, source preservation, exact delivery, and clean replay under the same image are used to determine completion. A state-conditioned experience reuse method is also designed for future planning and recovery, but has not yet been implemented or evaluated.

Existing experiments include complete system comparisons and component ablations. On eight previously examined tasks with two repetitions, both Forge and a strong tool agent completed 16 tasks. Forge used 22.9% less estimated model cost, with similar cumulative runtime. In a 30-run fixed-plan experiment, the three treatments completed 9/10, 10/10, and 10/10 tasks, respectively. All four direct configuration revisions completed without additional recovery model requests. A local tool recovery extension was also implemented and evaluated separately. After a context packaging repair, both recovery approaches completed 4/4 runs, but local tool recovery incurred 33.2% higher estimated cost including identical historical planning costs and 14.5% longer cumulative runtime. Original failures were retained under a separate identity. These observations support bounded claims about the current method and conditional recovery trade-offs. They do not establish population-level superiority or the effectiveness of the proposed experience mechanism.

**Keywords:** automated building; C/C++ repositories; state awareness; action selection; agent harness; reproducible verification
