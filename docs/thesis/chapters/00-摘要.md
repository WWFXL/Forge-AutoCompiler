# 面向C/C++仓库自动化构建的状态感知动作选择与验证方法研究

硕士论文阶段初稿v0.12，2026-11-17。

## 摘要

C/C++开源仓库构建需要协调依赖准备、配置生成、编译与产物确认。项目间构建入口、依赖组织和生成目录的差异，使固定命令模板难以覆盖真实任务；完全由大语言模型逐步操作，则会增加正常路径的交互和重复探索。本文研究在固定在线构建模型的条件下，如何利用当前执行状态与历史构建轨迹，改善动作选择、任务完成及模型开销。

本文提出模型规划、Workflow执行与状态驱动恢复相结合的方法。规划Agent依据作者材料生成阶段动作，Workflow执行并维护有效进展，状态选择器综合阶段目的、退出码、日志、实际配置和主要产物，选择继续执行、有依据的直接修订或Agent恢复。方案改变后保留有效前缀，重做受影响后缀；独立检查确认主要产物、源码保持、精确交付和同镜像干净重建。在此基础上，研究历史轨迹驱动的Harness更新，包括同项目成功方案复用、跨项目条件经验，以及根据轨迹诊断提出的规划提示、工具执行约束、依赖诊断与上下文管理更新。各候选通过固定版本比较决定采用与否。

九项目、三构建系统的54次主构建比较中，基础Forge、经验Forge和强工具Agent分别完成18/18、18/18和17/18。基础Forge模型估费比强工具Agent低60.5%，累计时间高42.2%。六次同条件成功方案复用均无需模型调用，实际重建及交付通过，时间比重新规划低12.1%；跨项目建议的收益则随材料适用性与恢复过程变化。固定初始方案的30次消融中，四次有依据的配置直接修订均完成且无需新增恢复请求。

历史轨迹驱动的更新揭示了规划与恢复之间的成本转移：第二轮提示候选H2初始费用下降18.2%，总费用却上升87.5%；12项目工具约束比较则多完成一项、总费低14.9%。进一步根据缺依赖轨迹改进环境查询、诊断记忆与错误类经验，在18项目、36次比较中，两组主构建均完成17/18、可复现交付均14/18，更新组模型估费低19.9%、累计时间低13.6%，初始投入增加而恢复费用下降53.3%。libffi案例中，恢复核实宏文件的开发包提供关系后补包，减少了替代宏探索。针对已有证据被本地字节门限阻断的问题，Token预算及完整工具消息管理使后续请求能够继续，真实构建完成。结果说明，Harness更新既涉及诊断和动作指导，也涉及工具反馈的持续可用性，应以全流程任务完成与开销评价。

## Abstract

Building C/C++ repositories requires dependency preparation, configuration, compilation, and artifact validation. Differences in build entry points, dependencies, and output directories limit fixed command templates. Delegating every step to a language model can instead add interaction and repeated exploration. This thesis investigates how execution state and historical build trajectories can improve action selection, task completion, and model cost under a fixed online build model.

The proposed method combines model-generated plans, workflow execution, and state-driven recovery. A planning agent derives stage actions from repository documentation. The workflow records execution and maintains valid progress, while the controller uses stage goals, exit codes, logs, configuration, and primary artifacts to choose continued execution, an evidence-backed direct revision, or agent recovery. A revised plan preserves its valid prefix and re-executes the affected suffix. Independent checks cover primary artifacts, source preservation, exact delivery, and clean rebuilding under the same image. Historical trajectories support validated same-project plan reuse, conditional cross-project guidance, and offline updates to planning instructions, tool execution constraints, dependency diagnosis, and context management. Fixed-version comparisons guide candidate adoption.

A 54-run comparison across nine projects and three build systems completed 18/18 tasks with base Forge, 18/18 with experience Forge, and 17/18 with a strong tool agent. Base Forge reduced estimated model cost by 60.5% while increasing cumulative runtime by 42.2%. All six exact-plan reuse runs rebuilt and delivered artifacts without model calls, taking 12.1% less time than replanning. Cross-project guidance showed task-dependent benefits and recovery costs. In a separate 30-run fixed-plan ablation, all four evidence-backed direct configuration revisions completed without additional recovery requests.

Trajectory-driven updates exposed cost transfer between planning and recovery: H2 reduced initial planning cost by 18.2% but increased total cost by 87.5%. Tool enforcement across twelve projects completed one additional task and reduced batch cost by 14.9%. Further updates introduced environment queries, diagnostic memory, and verified error-class guidance. In a 36-run comparison across eighteen projects, both versions completed 17/18 primary builds and 14/18 reproducible deliveries. The updated version reduced estimated model cost by 19.9% and cumulative runtime by 13.6%, with greater planning expenditure offset by a 53.3% reduction in recovery cost. In the libffi case, checking the package provider of a missing macro led to dependency installation and less exploration of replacement macros. Token-based budgeting and complete tool-message handling also resolved an observed local byte-limit blockage, allowing subsequent recovery and building to complete. These findings connect diagnostic guidance with continued access to tool evidence and support evaluating Harness updates through full-process completion and cost.

**Keywords:** automated building; C/C++ repositories; state awareness; action selection; Harness optimization; experience reuse
