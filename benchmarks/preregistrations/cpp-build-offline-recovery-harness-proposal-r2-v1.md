# R2 恢复 Harness 离线提案

日期：2026-11-10；Issue #721；身份 `cpp-build-offline-recovery-harness-proposal-r2-v1`。

本阶段分析历史结果并准备一次离线提案，不是构建方法比较。用户要求基于最新轨迹提出 R2，并指定 RichLab `gpt-6.1-sol`，后确认输入/输出各 1 美元/百万 Token。材料准备不收费；正式提案的新增费用及有效时窗尚待确认，不能续用旧授权。

## 研究问题与材料

R1 在 E53 中未优于 H0。固定初始规划 H0、线上 Flash、工具及共同执行器，新的恢复指导能否针对实际修订错误与额外探索提出值得比较的改变？本轮只生成候选，不回答其是否有效。

输入为 E53 全部 13 次自然恢复交接（7 槽、4 项目，H0/R1 5/8 次交接、19/32 次模型请求）及三系统各一正常成功边界。公开任务、实际失败交接、可见工具反馈、接受/拒绝反馈、提交动作及整槽结局均保留。每次最多前四/后四工具反馈，注明省略数；全部工具参数频次、来源路径和文件哈希保留。整槽结局不是局部恢复成功标签。未按成功或低费用筛恢复，不估异常发生率，不称最终 holdout。

当前共同提示、R1 原指导同时提供；R1 原提示底座已变化，因此仅将其指导装配到当前共同提示作差异参照，不冒充历史 R1 原始提示。#715/#717/#719 的生成文档、原生轻量验证、SONAME 交付、修订反馈、上下文压缩、国内 HTTPS APT 和成功重建标准明确告知优化器，不能计入候选收益。后续工程实建不是新 Agent 恢复轨迹，不发送私有参考、隐藏推理或个人知识库。

## 唯一允许的处理

仅生成整体替代 R1 附加指导的恢复 Harness；允许删减、重写或 `no_change`。初始规划 H0、线上 Flash、Workflow、工具、权限、资源、预算和验证器不改。指导不含项目名、精确成功命令、评价答案或宿主路径。每项诊断须引用存在的 evidence_id，输出完整 JSON，指导不超过 6000 UTF-8 字节。

## 待确认的调用边界

计划最多一次 RichLab Responses 请求，`gpt-6.1-sol`，最大输出 8192 Token，low reasoning，SDK `max_retries=0`、HTTP 240 秒。建议新增费用硬上限 1 美元、用户确认起 4 小时；输入/输出各 1 美元/百万 Token，共享该一次提案费用。按请求 UTF-8 字节数加输出上限及额外预留计算保守费用预留，材料最多 400000 字节；实际计费仍以返回 Token 和用户提供单价估算，非官方账单。

收到本身份预算/时窗授权后，运行收据必须绑定请求哈希、用户原文、开始/截止、模型及一次调用上限；校验后才读取已有 RichLab 凭据。不做额外服务探测或模型列表付费请求。只接受响应标识 `gpt-6.1-sol`，不继承旧 Astra/gpt-5.6 别名授权；服务实际后端仍不能仅凭标识证实。未知用量、错误标识、超预算/截止、无效输出均原样保留并停止，无自动重试或换模型。即使格式错误，已知 Token/费用仍先保存。

## 结束条件

保存模型原响应、诊断、候选、费用/时间和 H0/R1→R2 完整提示词差异，交用户审核。若 no_change 如实报告。比较次数为 0；本轮不采用 R2、不修改论文、不回填 E53。后续仍由用户下达比较指令，结果经审核并同意后才能写论文。
