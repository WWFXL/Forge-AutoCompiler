# rtorrent 标准生成命令形式资格 v1

承接 #583 的共同接口资格；这是一项独立、零 Provider 的生成输出校准，不是构建效果实验，不重开门禁身份。先冻结协议和组件，再执行一次，失败与未观察保留，不重试。

## 问题与依据

共同门禁的现有模板生成 `autoreconf -fi`，参考任务预声明 `autoreconf -ivf`，因精确命令形式不匹配而初始升级。该事实不能证明必须由模型处理源码依赖，不能把偶然参数形式差异算作模型规划必要性。为下一新比较准备合理生成权限，独立检查两个标准参数形式是否各自产生相同的预先冻结输出。

## 固定两case与边界

1. fi：从固定两源码归档独立解压，依次 `cd vendor-libtorrent && autoreconf -fi`、`autoreconf -fi`。
2. ivf：再从空目录独立解压，依次原参考的 `cd vendor-libtorrent && autoreconf -ivf`、`autoreconf -ivf`。

同一固定镜像（254系统包版本清单）、2 CPU、无网络；每命令120秒、总准入420秒、cleanup120秒，绝对截止沿本轮UTC2026-10-21T10:30:59.253248不延长。0模型凭据/Provider/Token/费用，不借旧余额。

新校准专属文件边界仅给两条fi调用添加与各自原ivf调用**相同的输入、输出路径和预先核验SHA**。818原作者文件（源码/测试/构建语义输入）及原40输出SHA保持，不按扩展名放行，不自动重写命令。两case使用同一事件监测边界包装，记录实际生成命令、完整输出、原文件SHA、40生成SHA与容器镜像/网络/CPU配置。任一不符合或cleanup失败停止，其余未观察；原门禁v1/v2权限及结果完全不改。

只有两case全部满足818原文件不变、40输出精确SHA相同、标准生成执行exit0、实际cleanup通过，才能说“当前固定版本/镜像下两种形式具有相同已核验生成输出”。仍未运行项目构建、作者测试、交付或clean replay，不能填这些层通过、宣称完整语义等价、工具模板可完成整个项目或无需Agent。未来若接纳fi，必须新任务/身份前瞻声明，并重新资格验证实际模板/失败恢复接线，不回填本轮旧拒答。
