# 显式目标约束与配置状态增强：配对增量实验

Issue631。研究问题：在同一任务、模型、执行器、预算与完整验收下，持久保持任务约束并在configure后核对实际配置，能否减少错误配置引起的无效编译和恢复调用，改善完整任务完成？本阶段先比较当前版与增强版，CXXCrafter系统比较随后独立安排。

- 六个固定已见任务：check/Autotools、simdutf/CMake、snappy/CMake、yaml-cpp/CMake、libtommath/Make、tinyxml2/Make，各两次新鲜重复，两版本共24槽；每对顺序前瞻交替，先后顺序见manifest。全部项目、版本和旧失败均已暴露，simdutf是开发动机案例，不声称holdout或未见泛化。
- 当前版：现有模型规划＋Workflow＋失败Agent。增强版：相同初始模型和恢复Agent，额外提供由公开任务静态解释的显式布尔目标；最后configure后及首次build前核对真实CMakeCache，保留值、类型、SHA256和命令前沿。值匹配为satisfied、冲突为violated，缺缓存/缺变量为unknown。普通文件缺失不能假装成配置值false。
- 当前可解释范围仅为原固定脚本的requirements字面布尔字典及显式默认静态库约束。没有这类合同的Make/Autotools任务保留原流程，单独列为适用范围观察，不据其结果声称已实现跨系统语义诊断。未支持表达式不猜测；没有目标不填“全部配置满足”。目标来自双方均可读取的原任务，不读取人工参考、历史成功命令或个人知识库。
- 直接动作最多一次且占用原恢复/命令预算：只对同根源码、同缓存、实际BOOL值、作者option或cmake_dependent_option/CTest开关有证据的偏离，追加显式configure步骤并使后续编译失效。保留原配置记录，追加步骤进入原命令审计和clean replay。HAVE_*等依赖探测值不强设；缺变量、未知依赖、复杂配置交原Agent。恢复仍携带原目标，后续再次观测，不许删掉约束。
- 两边继续使用deepseek-flash、thinking low、2CPU、原root/依赖网络与原源码归档。初始规划、目标材料、失败、纠错、恢复的全部模型费用计入；新增状态读取和配置修订耗时计入总时间。增强是约束呈现＋观察＋有界选择的组合，不把差值归为单一模块因果。最终原测试、源码保护、精确交付、同镜像完整重放及cleanup不变，不调整裁判制造成功。
- 时间合同统一：node1200秒、完整replay1200秒、清理余量300秒，新槽至少剩2700秒；请求准入仍600秒，HTTP240秒、SDK重试0。两臂均遵守同一合同；外层不能低于内部完整链所需余量。只在新有效时窗前段采集。触达截止则余槽未观察，不缩短重放来制造失败。
- 候选设计费用上限10美元，每槽沿原3美元/未知预留0.80美元。候选不产生支出授权；付费启动必须另有用户确认起止时间、累计上限、精确候选SHA及无自动重试。未知用量、身份异常或实际cleanup失败停止整批；不续旧身份、不补槽、不替换失败。准备/检查模式0凭据、0Provider。
- 主要报告完整完成数及配对变化、总费用、总耗时；辅助报告配置偏离次数、发现阶段、直接修订/Agent恢复次数、原始编译命令次数及配置后仍违背约束的案例。状态探测次数不得当编译次数。完整成功/真实未完成/时窗截断分别解释，不把false统一写成能力失败；费用包含失败，删失的短耗时不当效率收益。
- 输出完整逐槽表、分作用范围的配对结果、实际状态到动作轨迹和失败案例。小幅或有条件改善及成本取舍可支持继续研究；无改善则如实收缩主张。开发检查只覆盖当前变更，避免以资格/工程测试代替本24槽实验。当前增强尚无真实Provider效果结果。
