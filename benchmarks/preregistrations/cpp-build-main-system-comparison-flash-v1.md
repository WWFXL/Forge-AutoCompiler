# 简洁主构建三方法系统比较

- 身份：`cpp-build-main-system-comparison-flash-v1`，Issue #695。
- 问题：共同修复后的简洁主构建范围内，Workflow加失败恢复相比强工具Agent有何完成、在线费用和耗时取舍；两层经验在有/无成功方案任务中分别表现如何？
- 九开发项目：CMake jsoncpp/double-conversion/miniz，Autotools libite/libogg/libsrtp，Make highwayhash/xxhash/pigz；全部已有开发暴露，非holdout。每项目两重复×基础Forge/经验Forge/强工具Agent=54，三种方法位置与前序平衡，每项目第二重复逆序。不按本轮方法结果选样。
- 共同输入：main-build-v1简洁目标、相同源码归档/固定commit/镜像/x86_64/2并行；Agent获得原作者文件和任务，不获得独立参考命令或固定产物名。固定deepseek-flash thinking low、共同结构交付/对话/工具边界/命令与资源限制；工具Agent具有直接执行与反馈工具，两Forge使用相同规划和失败恢复Harness。
- 方法：基础Forge重新规划，Workflow执行，异常有限规则否则恢复Agent；经验Forge在三份精确命中时跳过初始模型，否则按已有检索注入至多2条4096字节建议，恢复任务开始同样只检索一次；强工具Agent逐步操作后提交。两Forge均使用相同不付费规则路由，无Jev。局部恢复仍为既有返回修订方案方式，不在本轮新增工具恢复处理。
- 经验分层：jsoncpp/libite/highwayhash的历史第一重复Flash成功动作，在新任务版本下零Provider实际重建/交付/干净重放确认后冻结；新任务来源不得只换标签，原指针/哈希/来源模型费用另列。其余六项目无精确方案，固定旧建议库且来源族隔离；本轮新成功方案仅存输出，不供后续槽检索，不声称持续学习。
- 主要结果：独立有效主产物、源码保持与cleanup共同构成`main_build_task_completed`；交付和clean replay分别列出。完整作者测试为`not_required`，不是通过；旧`full_completed`不进入新主表。记录全分母（每法18）、各层（6/12）和项目/重复，未启动/未观察分开。
- 费用：所有初始、读取、格式纠正、失败和恢复请求按输入$0.30/输出$1.20每百万Token保守估算；历史成功来源与旧库投入另列。报告总耗时及规划、恢复、命令、交付、重放时间。失败早停不可解释为加速；共同成功配对只作条件性辅助。
- 授权：用户本轮要求自主执行并不在电脑前；结合既往持续科研授权。助手自行限制新增10美元/UTC2026-11-05 07:44:31–15:44:31，准备计入，上界72、本协议54次；不是用户逐项指定，不继承旧账本。启动前绑定本协议manifest SHA与代码提交。Jev旧未知费用另列。
- 停止：无自动服务重试、不补槽；未知用量、模型标识异常、cleanup失败停止整批付费。单槽0.40美元上限、96请求/100万记录Token、2700秒；批次10美元/8小时上限。首次Provider请求核验服务，不单独付费canary。方法失败原样保留后继续其余槽；全局安全停止保留全部未启动。
- 解释边界：系统比较不是状态感知独立因果；总体依赖三复用/六无方案比例；两重复不是18个独立项目。不同版本、scope、批次不能合并成一个成功率，不由跨批差值推修复因果。负面结果保留，不在运行中改方法/阈值/样本。
